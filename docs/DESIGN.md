# AgentTerm design

How AgentTerm is built and why. For what it should do, see [SPEC.md](SPEC.md).

## Overview

```
 iPhone app ──┐                      ┌── PTY ── claude
              │  WebSocket           │
              ├──(Tailscale)──┐      ├── PTY ── codex
              │               ▼      │
 macOS app ───┴─(loopback)─ agenttermd ┴── PTY ── zsh
```

One process, `agenttermd`, owns every terminal session. The macOS app and the
iPhone app are both clients of it and speak the same protocol. The macOS app
has no private path to the terminals, so everything it can do is something the
iPhone can do too, and the protocol is exercised every time the Mac app is used.

## Modules

| Module | Platforms | Role |
|---|---|---|
| `AgentTermProtocol` | macOS, iOS | Message types, binary frame, pairing URL. No dependencies. |
| `AgentTermHost` | macOS | `PTYProcess`, `SizeArbiter`, `HostServer`, agent detection, Tailscale lookup, git diff, daemon launcher. |
| `agenttermd` | macOS | Command line entry point around `HostServer`. |
| `AgentTermClient` | macOS, iOS | `AgentTermConnection`, a WebSocket client built on Network.framework. |
| `AgentTermTerminal` | macOS, iOS | `TerminalController`: a SwiftTerm view bound to one session, plus shared colors. |
| `AgentTermMac` | macOS | SwiftUI app. |
| `iOS/AgentTerm` | iOS | SwiftUI app. Not part of the package. |

The package is plain SwiftPM. The iPhone app needs an app bundle, so it has an
Xcode project, generated by XcodeGen from `iOS/project.yml` and not checked
in. It depends on the package's `AgentTermProtocol`, `AgentTermClient` and
`AgentTermTerminal` products.

The client uses Network.framework rather than `URLSession` because the host
speaks plain `ws://`. App Transport Security would refuse that for
`URLSession` on iOS, and an exception for arbitrary loads is broader than
needed. The connection is made to a URL endpoint: with a host and port
endpoint the WebSocket handshake is aborted.

## Pseudo terminals

`PTYProcess` starts the child through `agentterm_spawn_pty`, a small C function
(target `CAgentTermPTY`) that forks, calls `setsid()` and `ioctl(TIOCSCTTY)` on
the slave side, sets the window size, and execs.

- The pseudo terminal has to be the child's *controlling* terminal, or the
  child gets no terminal signals: no SIGWINCH on resize, so a full screen
  program never redraws for a new size. `posix_spawn` cannot do this, because
  it cannot run an ioctl in the child, and opening the slave from a spawn file
  action does not make it the controlling terminal. An earlier version did
  exactly that and seemed to work, because bash claims the terminal itself at
  start-up. zsh does not, so everything started through a zsh login shell,
  which is every agent, ran without one.
- Between `fork()` and `execve()` the child only calls async-signal-safe
  functions, which is what makes `fork()` acceptable in a threaded process.
- The child closes every descriptor but the terminal, so the daemon's sockets
  and other terminals are not passed on, and resets signal handling.
- A failed exec is reported back through a close-on-exec pipe.
- Output is read by a dispatch source on the host queue. Writes run on a
  separate queue because they block when the program is not reading, and
  output must keep flowing meanwhile.
- When the child exits, pending output is drained before the exit is reported.

Programs are started through the user's login shell (`$SHELL -l -i -c
<command>`), so they get the same `PATH` and environment as in a regular
terminal. The environment sets `TERM=xterm-256color`, `COLORTERM=truecolor`
and a UTF-8 locale when none is set.

## Terminal size with several clients

A PTY has one size, but a Mac window and an iPhone screen differ. `SizeArbiter`
implements "the client being used wins":

- Every attached client reports the grid that fits its view, and reports
  again when that changes (`resize`).
- The driver is the client that most recently took control (`takeControl`) or
  typed. The PTY takes the driver's size.
- Attaching and resizing never make a client the driver, unless it is the only
  one attached. The Mac app attaches to every session to show it; if that took
  the size, a session opened on a phone would jump to the Mac's size a moment
  later and the phone would only see a corner of it.
- A client's reported size is kept while another client drives, so typing
  there later switches to its current size at once.
- When the driver detaches, the most recently active remaining client becomes
  the driver. With no client left the size stays as it is.
- After every change the host sends `resized` to each attached client with a
  `driver` flag. A client that is not the driver shows the driver's grid
  rather than its own, so the content lines up.

tmux's rule, the smallest attached client, was rejected: a phone left
connected would keep the Mac window small.

Size reports are debounced by 120 ms, because layout changes arrive in bursts
(a window being dragged, the iOS keyboard sliding in) and each report makes
the program redraw.

`TerminalController` keeps two sizes: the natural size that fits
its view and the foreign size imposed by another driver. A layout change while
another device drives updates the natural size without taking control.

The iPhone attaches only to the session on screen, takes control of it when
it opens, and detaches when leaving it, so the Mac gets its size back as soon
as the phone stops looking. The Mac takes control only when the user types or
asks for it.

While a session has a foreign size, every client's emulator takes that grid,
so all of them draw exactly what the driver sees. The terminal view is then
made exactly as large as the grid (SwiftTerm's `getOptimalFrameSize()`), and
the container decides how to show it:

- **Mac**, where the foreign grid is usually a phone's and small: centered,
  with a frame and a dimmed surround.
- **iPhone**, where it is usually a Mac's and large: scaled down with a view
  transform until the whole grid fits, against the top.

Because the view no longer has the container's size, what SwiftTerm reports
as its size is the foreign grid. The grid that would fit the container, which
is what the client asks for when the user comes back to it, is worked out by
`TerminalController.containerResized` from the cell size. Once the client
drives again the view fills the container and SwiftTerm's own figure is used.

Keeping the Mac's own, larger grid and letting the narrower output flow into
it was tried and dropped: it reads well for programs that draw relative to
the cursor, but the picture on the Mac is then not the picture on the phone.

### The size a session starts with

A session is created with the grid that fits the place its terminal will be
shown in, worked out by `TerminalMetrics` from that place's size and the
font before any terminal view exists. With a guessed size the shell draws
its first prompt for the wrong width. zsh then leaves a stray "%" on screen:
it prints that mark and pads the line to the width it believes in, and the
padding wraps where the real width is smaller.

The same mark can still show after the width changes later (rotating the
phone, changing the text size, another device taking over), because the
padded line is already on screen and gets wrapped again.

### Input that is not typing

Every attached emulator answers the program's queries (cursor position,
device attributes, colors), and reports focus changes and pointer movement.
These arrive the same way keystrokes do. `TerminalReply` recognizes them, and
the host:

- does not count them as activity, so they never make a client the driver.
  Before this, Claude Code's start-up queries were answered by the Mac's
  emulator, the host took that for typing on the Mac, and a session opened on
  a phone jumped to the Mac's size;
- passes on only the driver's, so the program gets one answer, from the
  emulator whose grid matches the PTY.

## Protocol

WebSocket over TCP, default port 7717.

**Text frames** carry JSON messages, encoded with Swift's synthesized `Codable`
for enums (`{"attach":{"session":1,"size":{"cols":48,"rows":30}}}`).

Client to host:

| Message | Meaning |
|---|---|
| `hello(token, client)` | Must come first. Wrong token closes the connection. |
| `list` | Ask for the session list. |
| `agents(refresh)` | Ask which agent CLIs are installed. |
| `create(command, cwd, title, size)` | Start a session and attach to it. |
| `attach(session, size)` / `detach(session)` | Start or stop receiving a session. |
| `resize(session, size)` | Report that this client's grid changed. Applied only if it drives the session. |
| `takeControl(session, size)` | The user is using the session here: become the driver at this size. |
| `kill(session)` | Hang up the session (SIGHUP, then SIGKILL after 3 s). |
| `addFolder(path)` / `removeFolder(path)` | Change the shared folder list. |
| `diff(path)` / `diffFile(path, file, staged)` | A folder's uncommitted changes without the diffs, then one file's diff: its staged part, or what is only in the working tree. |
| `gitStage(path, files)` / `gitUnstage(path, files)` / `gitCommit(path, message)` | Change what the next commit contains (no files means all), and commit it. Answered with `diff`, after an `error` carrying git's words if it failed. |
| `gitPush(path)` / `gitPull(path)` | Push the checked out branch, or bring in what its upstream has. Answered the same way, then with `gitSynced(path)`: a `diff` alone may answer something asked while git was still at work. |
| `writeCommitMessage(path)` / `cancelCommitMessage(path)` | Have an agent write the message for what is staged, or stop it. Answered with `commitMessage(path, message)`, whose message is nil when it was stopped or failed. |
| `setCommitWriter(settings)` | Which agent writes commit messages, on which model, with which prompt. |
| `setKeepAwake(on)` / `setKeepAwakeOptions(options)` | Keep the Mac awake while sessions run, and how: the display too, only on power, for how long. |
| `setDisplaySettings(settings)` | How things are shown on every device: the temperature's unit, diffs in one panel or two, changes as a list or a tree. The host keeps it in `settings.json` and passes it on as `displaySettings`. A host that keeps none yet sends nil, and the client hands it its own. Each app also writes the values to its own preferences, which is what its views read. |
| `sshHosts` / `connectSSH(host, size)` | The hosts of the Mac's SSH configuration, and `ssh <host>` in a new session. |
| `history(path)` | Conversations agents had in a folder, or everywhere when `path` is nil. |
| `resume(agent, sessionID, cwd, size)` | Reopen a conversation in its agent, in a new session. |
| `handoffPlan(agent)` | What the receiving agent would be told, to show it before handing off. |
| `handoff(agent, sessionID, cwd, target, plan, prompt, note, size)` | Hand a conversation to another agent, in a new session. |
| `files(path)` / `readFile(path)` / `writeFile(path, text)` | A folder's files, what a file holds, and saving it. |
| `createFile(directory, name, isDirectory)` / `renameFile(path, name)` / `trashFile(path)` | Change the files. Answered with the folder's listing. |
| `listDirectory(path)` | The folders inside a folder, or inside home. |

Host to client: `welcome`, `sessions`, `agents`, `folders`, `attached`,
`resized`, `exited`, `error`, `diff`, `diffFile`, `history`, `directory`,
`commitMessage`, `sshHosts`, and for pairing `paired`, `pairingCode`,
`devices`. The session list, the folder list and the host's settings
(`tabLayout`, `keepAwake`, `keepAwakeOptions`, `commitWriter`) are pushed to
every client when they change.

The protocol version is 6 since 0.4.0, which added the messages for push
and pull, commit messages, keep awake options and SSH hosts.

The folder list is host state, saved in `folders.json`, so the Mac and the
iPhone show the same projects and the phone can start an agent in any of them.

**Binary frames** carry terminal bytes: one byte kind (0 output, 1 input), the
session id as 4 bytes big endian, then the raw bytes. Input from a client that
is not attached to the session is dropped.

## Attaching to a running session

The host keeps the last 4 MB of each session's output and replays it to a
client that attaches, so a phone that opens a session can scroll back
through what happened before it looked. The replay goes out in pieces of
256 KB, since one message may not be larger than 4 MB, and once the oldest
output has been dropped it starts at the beginning of a line rather than
in the middle of one. The buffer is cut back to its limit only when it is
a quarter over, because cutting copies it. Each emulator keeps 20,000
lines to scroll back through (SwiftTerm's own default is 500, which threw
most of a replay away as it arrived). For full screen programs the replay
relies on the program redrawing, which happens when the attach changes the
size.

The replay was drawn for the session's grid, so the emulator takes that
grid before the first replayed byte (`TerminalController.beginReplay(size:)`),
and keeps it until its view has been laid out and the grid that fits is
known. Before 0.4.0 the emulator replayed at the size it happened to be
created with and then went to 80 × 24: lines wrapped in the wrong places,
and a program that redraws in place, an agent above all, showed a broken
screen. Nothing made it draw again, because the Mac attaches at the
session's own size, so the size never changed. It showed whenever the app
was opened with an agent already running, which is what the first launch
after an update is.

## Agent detection

`AgentDetector` runs one script through the login shell that resolves each
known CLI with `whence -p` (zsh), `type -P` (bash) or `command -v`. The result
is cached by the host and sent on request; `agents(refresh: true)` runs it
again. Clients only offer agents with a path.

## Changes pane

The right side of the Mac window has two tabs, Git and History.

The diff of a file scrolls sideways as far as its longest line, with scroll
bars that stay visible: macOS hides them until you scroll, which would give
no hint that a line continues.

The two-panel view is laid out by `SplitDiff.rows` (in `AgentTermProtocol`)
from the same unified patch: lines both sides share are one row, a run of
removed lines followed by added ones is paired line by line, and what one
side has more of faces an empty row. Line numbers come from the hunk
headers. `SplitDiffView` (in `AgentTermTerminal`) draws it for both apps: one
vertical scroll view holding two horizontal ones, so the panels move down
together and sideways apart. Its rows are not lazy, since a lazy stack
inside the sideways scroll would have no height to be lazy in, so it shows
at most 2,500 rows and says when it left some out.

`GitDiff` shells out to `git`: `diff --cached` for what is staged, `diff` for
what is not, and `ls-files --others` plus `diff --no-index` for untracked
files, then splits the output per file. Renames are not detected
(`--no-renames`), so every entry is one path that can be staged on its own.
`GitActions` runs `git add`, `git restore --staged` (`git rm --cached`
before the first commit) and `git commit`, with `--literal-pathspecs` so a
file name is never read as a pattern.

The snapshot also says which branch the checked out one follows and how
far the two are apart (`git for-each-ref` with `%(upstream:short)` and
`%(upstream:track)`, one cheap call that asks nothing of the remote), and,
for a branch that follows none, the remote a first push would go to:
`origin`, else the first remote. `GitActions.push` runs `git push`, or
`git push --set-upstream <remote> <branch>` for that first push;
`GitActions.pull` runs `git pull --no-edit`, so it merges or rebases as the
repository is set up to. Both run with `GIT_TERMINAL_PROMPT=0`, no askpass
program and `SSH_ASKPASS_REQUIRE=never`: credential helpers and the SSH
agent still answer, and anything that would wait for typing fails with
git's own message, since there is no terminal to type in. A pull that
leaves a merge or a rebase under way is aborted, unless one was already
under way before it, which is the user's and is left alone.

## Commit messages written by an agent

`CommitWriter` builds the agent's input: the prompt, the list of staged
files with their counts (`git diff --cached --stat`), then each file's
diff, capped at 8,000 characters a file and 60,000 in all; files past that
are named without their diff. It then runs the agent once, without a
terminal, through the login shell as sessions are:

| Agent | Run as |
|---|---|
| Claude Code | `claude -p --no-session-persistence --strict-mcp-config --tools '' --model <m>`, the input on stdin |
| Codex | `codex exec --skip-git-repo-check --ephemeral --sandbox read-only -o <file> -`, the input on stdin |
| Antigravity | `agy --print "<input>"` |
| Copilot CLI | `copilot -p "<input>" --silent --no-custom-instructions --no-ask-user` |

The agent runs in `<state>/commit-writer`, not in the project: a headless
run inside the project would leave a conversation there, which the History
tab would list and `SessionSummaries` could pair with a session running in
that folder. Claude Code and Codex are told not to save one at all; what
Antigravity and Copilot save belongs to that folder of the host's, which
History leaves out. No agent is given a way to change anything: no tools
for Claude Code, a read-only sandbox for Codex, and for the other two no
approvals, which without a terminal means every tool request is refused.
The answer is taken out of a code fence or quotes if it came in one, and is
only ever put in the message field. A run can be stopped; it is also
stopped after three minutes.

The settings (agent, model, prompt) are the host's, in `settings.json`, so
the Mac's Write button and the iPhone's do the same. Both apps ask the host
with `writeCommitMessage`, the Mac too, though it runs git itself.

## How the Mac is doing

`SystemSampler` measures the Mac itself every three seconds while a client
is connected, and the host sends the result as `systemStats`:

| Figure | From |
|---|---|
| Processor | `host_statistics(HOST_CPU_LOAD_INFO)`: busy ticks over all ticks between two samples |
| Memory | `host_statistics64(HOST_VM_INFO64)`: app memory, wired and compressed, less what can be purged, as Activity Monitor counts it; `hw.memsize` |
| Network | `getifaddrs`: bytes in and out of every interface but the loopback, between two samples |
| Temperature | The hottest of the processor's sensors, through IOKit's HID event system; `ProcessInfo.thermalState` always |
| Battery | `IOPSCopyPowerSourcesInfo`: charge and whether it is charging |
| Uptime | `kern.boottime` |

The calls that read the temperature sensors are in IOKit but not in its
headers, so `SystemSampler` declares them itself. Where they find no
sensor, an Intel Mac for one, no temperature is sent and the apps show the
thermal state in words. Figures are rounded (a tenth of a gigabyte, a
kilobyte a second) so a Mac at rest is not announced again and again.
`SystemStatsView`, in `AgentTermTerminal`, draws them for both apps.

## SSH hosts

`SSHConfig.hosts` reads `~/.ssh/config`: the names after `Host`, following
`Include` (relative to `~/.ssh`, with `~` and wildcards) up to eight deep.
Patterns are skipped, and so is any name that is not plain (letters,
digits, `-`, `_`, `.`), because a name is put on a command line. Only the
names are sent to a client. `connectSSH` takes a name the host finds in
its own reading of the configuration, never a command.

## Keeping the Mac awake

`SleepGuard` holds an IOKit power assertion: `PreventUserIdleSystemSleep`,
or `PreventUserIdleDisplaySleep` when the display is to stay on. The host
holds it while the switch is on, a session exists, and, with "only on
power", `IOPSGetProvidingPowerSourceType` does not say battery; it looks
again on its timer, so plugging in or pulling the cable is followed within
seconds. A hold given a length carries the time it ends in the options;
when that passes the host switches it off and tells the clients. The
switch, the options and the end time are kept in `settings.json`. The Mac app calls it directly every few seconds while it is
in front. The iPhone asks the host: `diff` returns the list of files without
their diffs, which can be megabytes, and `diffFile` returns one file's diff.
The host keeps the last result per folder for 20 seconds so opening a file
right after the list does not run git again. Git and file reading for
clients run on a separate concurrent queue, off the queue that moves terminal
bytes.

## Files tab

`FileBrowser` (in `AgentTermHost`) lists a folder, reads a file and tells text
from images, other binaries and files too large to open, and creates,
renames, writes and trashes. Names are checked to be a single path
component, and an existing name is never overwritten. The Mac app calls it
directly; it is not in the protocol, so the iPhone has no Files tab.

`FilesModel` holds the tree (folders load when opened and are read again
every 5 seconds while the app is in front) and the open documents. Documents
belong to the window, not to the folder being browsed, so switching folders
does not close a file with unsaved edits. `active` names the document in
front; it is nil while a terminal shows. The tab strip lists sessions, then
documents, and the tab shortcuts count across both.

The editor is an `NSTextView` whose text storage is Highlightr's
`CodeAttributedString`, which recolors text as it is edited using
highlight.js. Markdown is rendered by MarkdownUI, with its code blocks
colored by the same highlighter. The editor and the previews live in the
`AgentTermEditor` target, which both apps use: on the iPhone the editor is a
`UITextView` on the same text storage.

The Mac reads and writes files itself. The iPhone asks the host: `files`
lists a folder, `readFile` returns text, or an image's bytes up to 8 MB,
`writeFile` saves, and `createFile`, `renameFile` and `trashFile` change the
tree and are answered with the folder's new listing. They run `FileBrowser`,
the same code the Mac app calls.

Mermaid diagrams are drawn by `MermaidView`, a `WKWebView`, since Mermaid is
a JavaScript library. `mermaid.min.js` (11.4.1, MIT) is checked in under
`Sources/AgentTermEditor/Resources` and shipped in the apps, so nothing is loaded
from the network: the page has a content security policy that allows no
remote source at all. The diagram's source goes into the page as escaped
text, and Mermaid runs with `securityLevel: 'strict'`.

Highlightr and `AgentTermEditor` each bring a resource bundle, which
`scripts/bundle-mac.sh` copies into the app's `Contents/Resources`.

## Channels

`AppChannel.current` is `.release` only when the code runs in a bundle whose
identifier is `com.manhpham.agentterm`; a development bundle, a bare
`swift run` and the test runner are `.dev`. The channel decides the app's
name, the folder the host keeps its files in, the default port and the scheme
of pairing links, which keeps a development build apart from an installed
release. See docs/RELEASE.md.

## Usage

`SessionInfo.usage` carries a `SessionUsage`: model, context tokens and
window, limits (window in minutes, percent used, reset time), premium
requests. The host fills it on the same six-second timer that names
sessions, so both apps get it with the session list.

`AgentUsage` reads the end of the conversation's file, the last 768 KB:
Claude Code's last reply with a `usage` object, Codex's last `token_count`
event (which carries `rate_limits`), Copilot's last `session.usage_record`,
Antigravity's last step with `input_tokens`.

Claude Code writes its rate limits nowhere, but hands them to its status
line command. So a session whose command is `claude` is started with
`--settings '{"statusLine":{"type":"command","command":"<agenttermd> statusline <file>"}}'`.
`StatusLineRelay` saves the JSON it is given to `<state>/usage/session-<id>.json`,
then runs the status line found in the project's or the user's settings
with the same input and prints what that prints. The host prefers this
report over the conversation file, since it has the limits and the size of
the context window. The file is removed when the session ends.

What an account has left is a second thing, `AccountUsage`, kept per agent
and sent to clients as `accountUsage` when it changes. `AccountUsageFetcher`
asks the agent's service, on the work queue, every five minutes while that
agent has a session:

| Agent | Sign-in read from | Asked |
|---|---|---|
| Claude Code | Keychain item `Claude Code-credentials`, else `~/.claude/.credentials.json` | `GET api.anthropic.com/api/oauth/usage?cedar_ember=1` (the query asks for banked limit resets) |
| Codex | `$CODEX_HOME/auth.json` | `GET chatgpt.com/backend-api/wham/usage`, and `wham/rate-limit-reset-credits` when resets are banked |
| Antigravity | Keychain item `gemini` / `antigravity` (go-keyring), else `~/.gemini/antigravity-cli/antigravity-oauth-token` | `POST cloudcode-pa.googleapis.com/v1internal:loadCodeAssist`, then `retrieveUserQuotaSummary` |
| Copilot CLI | `COPILOT_GITHUB_TOKEN`, `GH_TOKEN`, `GITHUB_TOKEN`, else `gh auth token` | `GET api.github.com/copilot_internal/user` |

Google answers by client name: the request says `antigravity/cli/<version of agy>`,
which is what returns every group of models.

The rules it keeps: HTTPS only, to those hosts only, redirects not followed;
a sign-in is never refreshed or written back, since renewing it is the
agent's business and doing it here could sign the agent out; an expired one
is not sent at all; nothing of it is logged, stored or put in a message to
a client. The outside world is passed in as `Environment`, so the tests run
against canned answers and never touch a keychain or the network.

## Conversation history

`AgentHistory` reads the files each agent CLI keeps about its own
conversations and lists those that ran in a folder. Conversations of
subfolders are left out by default, so that a workspace holding several
projects does not list every project's conversations as its own:

| Agent | Where it looks | Title | Resume command |
|---|---|---|---|
| Claude Code | `~/.claude/projects/<folder>/<session>.jsonl` | newest `ai-title` line, else the first prompt | `claude --resume <id>` |
| Codex | `~/.codex/sessions/**/rollout-*.jsonl` (first line has id and directory) | first prompt, from `~/.codex/history.jsonl` | `codex resume <id>` |
| Antigravity | `~/.gemini/antigravity-cli/cache/conversation_metadata.json` | its `Title` | `agy --conversation <id>` |
| Copilot CLI | `~/.copilot/session-state/<id>/workspace.yaml` | its `name`, else the first prompt | `copilot --resume=<id>` |

None of these are documented formats, so every reader treats missing or
unexpected data as "no conversations", and a CLI update can empty a section
until the reader is adjusted. Session files grow to many megabytes, so only
the first 256 KB and the last 64 KB are read. Session ids are put on a command
line that a shell runs, so ids with anything but letters, digits, `-`, `_` and
`.` are dropped.

The Mac app calls this directly, since it runs where the files are. The
iPhone asks the host with `history`, `resume` and `handoff`. For `resume` the
host builds the command itself from the agent and the id, after checking
both; for `handoff` it looks the conversation up again on its own disk, so a
client only ever names a conversation and never supplies a path or command.

## Session names

`SessionInfo` carries `agent`, `summary` and `conversationID`. The host fills
them in, so every client shows the same name without reading any files:

- `agent` comes from the command the session was started with.
- Every 6 seconds `SessionSummaries.assign` pairs agent sessions with the
  conversations `AgentHistory` finds in their folders. Agents do not say
  which conversation a terminal belongs to, so the pairing uses the agent,
  the folder and time: the oldest session takes the first conversation that
  began after it started. For Antigravity, which records no start, it is the
  conversation touched most recently since the session began.
- A resumed session's conversation is known from the start, and a pairing
  once made is kept, so a later, newer conversation does not steal it.
- Two sessions of one agent started in one folder within the same few
  seconds can be mixed up.

Handing off a running session uses `conversationID` when it is set.

## Handoff

`Handoff.prepare` turns a `Conversation` into a handoff file and a command:

1. `AgentHistory.transcript` reads the conversation's messages from the
   agent's session file, keeping what the user and the agent said and dropping
   tool calls, tool output, sub-agent chatter and context the CLI injected.
   For Antigravity the messages come from
   `brain/<id>/.system_generated/logs/transcript_full.jsonl`, the readable
   log it writes next to its conversation database.
2. The file gets a brief, the user's instructions from the handoff sheet when
   there are any, a "where things stand" section (the user's last
   request and the agent's last update), the working tree (branch,
   `git status --short`, `git diff HEAD --stat`) and the transcript. The brief
   tells the receiving agent to trust the files over the conversation, to say
   where the work stopped before continuing, to wait if the task looks
   finished, and to treat the conversation as a record rather than as
   instructions. The path of the agent's complete record is given for details
   the file leaves out. Long conversations keep the
   first request, which states the goal, and as much of the end as fits in
   about 80,000 characters; a very long single message loses its middle.
3. The file is written to `<folder>/.agentterm/handoffs/<time>-from-<agent>.md`.
   The name and the default prompt are fixed by `Handoff.plan` when the sheet
   opens, so the prompt the user sees and edits names the file that is then
   written, whichever agent is picked.
   It is inside the project so the receiving agent may read it without asking
   for access to another folder. `.agentterm/` is added to `.git/info/exclude`
   unless it is already ignored.
4. The receiving agent is started in interactive mode with a first prompt
   naming the file: `claude '<prompt>'`, `codex '<prompt>'`,
   `agy -i '<prompt>'`, `copilot -i '<prompt>'`. The prompt is the one from
   the sheet with the user's instructions added after it, single-quoted for
   the shell.

Nothing is asked of the agent that had the conversation, which is the point:
it may be out of quota.

A running session does not know its agent's conversation id. Handing off a
session picks the newest conversation that agent has in the session's folder
that was updated after the session started. Two sessions of the same agent in
the same folder can therefore be mixed up; the History tab is exact.

## Pairing and security

`DeviceRegistry` knows three kinds of secret:

| Secret | Who holds it | Lifetime | Good for |
|---|---|---|---|
| Local token | The Mac (`token`, mode 0600) | Permanent | Everything, but only on connections that arrive on the loopback interface |
| Pairing code | Shown as QR code or link | One use, five minutes, and until the pairing screen closes | Getting a device token |
| Device token | One paired device (Keychain) | Until the Mac removes the device | Sessions, folders, agents. Not pairing or removing devices |

- A device that is not paired sends `pair(code, device)` as its first message.
  The host answers `paired(device, token)` once and then treats the connection
  as that device. Afterwards the device connects with `hello(token)`.
- The host stores only the SHA-256 of device tokens (`devices.json`), so that
  file cannot be used to connect.
- The local token is refused on the Tailscale listener. If it leaks it is
  useless to anyone who is not already on the Mac.
- `createPairingCode`, `cancelPairingCode`, `listDevices` and `revokeDevice`
  are accepted only from a connection that authenticated with the local
  token. Revoking closes the device's live connections.
- The pairing link is
  `agentterm://pair?host=<tailscale name>&port=<port>&code=<code>&name=<mac>`.
- `agenttermd pairing-link` asks the running daemon for a code and prints the
  link. The iOS Simulator has no camera, so `scripts/pair-ios.sh` uses it.
- `Tailscale.status()` decides what the pairing screen shows. Tailscale counts
  as installed when its app or command line tool is found; as ready when the
  Mac has an address in Tailscale's range and the CLI, if it answers, reports
  the backend as running. An address alone is enough where the CLI is missing.
  The screen re-checks every 3 seconds while it is open.
- The host listens on `127.0.0.1` and on the Mac's Tailscale address
  (100.64.0.0/10), found with `getifaddrs`. It checks every 15 seconds so it
  follows Tailscale going up, down or changing address. It never listens on
  other interfaces.
- The WebSocket itself is not encrypted. Loopback traffic stays on the Mac and
  Tailscale traffic is encrypted by WireGuard.
- A token is still required on Tailscale, because other devices and shared
  nodes in a tailnet can reach the port, and the port is shell access.
- Token and code comparison is constant time. Unauthenticated connections are
  closed after 10 seconds.

## Vietnamese input

- **Host**: bytes pass through untouched and the locale is UTF-8. Covered by
  tests at the PTY level and end to end.
- **macOS**: SwiftTerm's view implements `NSTextInputClient`, so input methods
  that use marked text compose at the cursor. Tools that retype with
  backspaces send DEL bytes followed by the new text, which the shell and the
  agents handle themselves. Both paths are checked by hand, against the
  matrix in the spec.
- **iPhone**: prose goes through a native compose field and is sent as
  complete text, so the emulator never sees a composition. The key bar sends
  control keys directly. The text and the Return that submits it are sent 80 ms
  apart, because agents treat a burst ending in Return as a paste and do not
  submit it. Multi-line text is wrapped in bracketed paste.

## macOS app structure

- `AppModel` holds all state: connection, folders, sessions, agents, the diff
  and one `TerminalController` per session.
- `TerminalController` wraps a SwiftTerm `TerminalView` and is its delegate.
  Terminal views are kept alive while their session runs, so switching
  sessions keeps scrollback.
- If the app cannot connect, it starts the `agenttermd` that sits next to its
  own executable, in a new session so it outlives the app, and retries.

## iPhone app structure

- `PhoneModel` holds the paired Macs, the connection and the single
  `TerminalController` for the session on screen.
- There is one connection at a time, to the Mac on screen. Switching Macs
  closes it and opens another, so a Mac that is not on screen costs nothing
  and its sessions are not resized by this phone.
- The paired Macs, each with this phone's token for it, are kept in the
  Keychain as one list. Pairing again with a Mac replaces its entry.
- `PairView` scans with VisionKit's `DataScannerViewController`. Where there
  is no camera (the simulator) the link can be entered as text, and the app
  also opens `agentterm://pair` links.
- `TerminalScreen` stacks the terminal, the key bar and the compose field.
  What is written in the compose field and not sent is kept per session on
  the phone (`PhoneModel.composeDraft`), so it is there again after leaving
  the terminal or closing the app. The Mac needs nothing for this: what is
  typed there is already in the program's own input, in the session.
  The keyboard shrinks the terminal's frame, which resizes the PTY.
- While the app is in front it reconnects after a drop, at once the first
  time and then every few seconds, and re-attaches to the session that was
  open. The terminal screen says so meanwhile.
- A drop is rarely announced: the network changes or the app was asleep,
  and what is sent just goes nowhere. `AgentTermConnection` therefore asks
  a host that has been quiet for four seconds for a WebSocket pong, and
  closes a connection that does not answer within six, which is what lets
  the app connect again. Coming back to the front asks at once. Bytes that
  keep arriving count as an answer: a large message over a slow link, a
  replay or a file, holds the pong back behind it, and that link is slow,
  not gone.

## Testing

- `swift test` covers the protocol, PTY behavior, the size arbiter, parsing
  and the host server end to end over a real loopback WebSocket.
- `scripts/test-ios.sh` runs an XCUITest in the simulator against two
  throwaway hosts: pair by link, start a shell, send Vietnamese text from the
  compose field, use the key bar, go back, pair the second host, and switch
  between the two.
- `AGENTTERM_STATE_DIR` moves the host's token, folder list and log to another
  folder, which keeps test hosts away from the real pairing.

## Known limitations

- The iPhone app has not been run on a real device.
- Session rows on the iPhone are named after the session's working directory
  when it is not a listed folder; the home directory shows as the user name.

- Attach replays raw bytes instead of a screen snapshot. What a program
  drew for another width, before the session was resized, reads badly
  further up.
- SwiftTerm resets some terminal modes when its grid is resized from code,
  which happens when another device takes over the size.
- A terminal wider than the Mac window (a phone in landscape next to a narrow
  window) is clipped rather than scaled.
- The host does not apply backpressure to a slow client.
- The daemon is started by the app, not as a login item, so after a reboot
  nothing runs until the app is opened.
